# SQL data reference

Names, entries, strings, byte search, data reads, and data-oriented views.

### names

- Exact lookup pushdown: `address = <ea>` and `name = '<exact name>'`.
- `is_auto`: 1 if the current name is auto-generated by IDA, 0 if it is user- or tool-provided.
- Row fields are resolved lazily. `count(*)` and `SELECT address, name ...` avoid the extra per-row name-origin lookup needed for `is_auto`.

### entries

- Entry/export points. Columns: `ordinal`, `address`, `name`.
- `name` may be empty for ordinal-only exports.

### db_info, segments, imports

- Full scan is cheap, no pushdown needed.
- `segments.perm`: permission bitmask -- `1` execute, `2` write, `4` read.
- `segments.class` is IDA's segment-class string (`CODE`, `DATA`, ...).

### strings

- Exact lookup pushdown: `address` EQ.
- `type`: raw IDA string-type code (`ida_nalt.STRTYPE_*`); `0` is C/ASCII.
- `string_value` is the decoded text.

### bin_search

- Pushdown required: `pattern` EQ (hex byte string, IDA syntax with `?` wildcards).

### string_refs

- `string_refs`: JOIN of `strings` + `xrefs`. Only includes refs from within functions (`from_func != 0`).

### Memory-read functions

Read raw bytes from the IDB. All return NULL on NULL input.

`read_u8(ea)`: unsigned 8-bit value at ea.

`read_u16(ea)`: unsigned 16-bit little-endian value at ea.

`read_u32(ea)`: unsigned 32-bit little-endian value at ea. Equivalent to `ida_bytes.get_dword(ea)`.

`read_i32(ea)`: signed 32-bit little-endian value at ea.

`read_u64(ea)`: unsigned 64-bit little-endian value at ea. Equivalent to `ida_bytes.get_qword(ea)`.

`read_i64(ea)`: signed 64-bit little-endian value at ea.

`read_rel32(ea)`: resolve a 32-bit relative pointer: `ea + i32_at(ea)`. Returns the absolute target address, or NULL if the offset is zero (common "no target" sentinel in Swift/ObjC metadata).

`read_bytes(ea, size)`: raw bytes as a hex string. Capped at 4 KiB; raises on larger sizes.

`read_cstr(ea)`: null-terminated C string at ea, decoded as UTF-8 (lossy). Returns NULL if no string.

These compose naturally with other functions and tables:
```sql
-- Resolve a Swift relative pointer and get the name at that address
SELECT name_at(read_rel32(0x100001000))

-- Read a dword from each function's entry point
SELECT name, hex(read_u32(start_ea)) AS first_insn FROM funcs LIMIT 10

-- Follow an ObjC class pointer chain
SELECT read_cstr(read_u64(read_u64(address + 0x20) + 0x18)) AS class_name
FROM names WHERE name LIKE '__objc_classlist%'
```
